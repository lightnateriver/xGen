# Native-stream 在线发布修复

本修改修复 CUDA 在线全并行 Streaming 配方的文件交付，不改变模型权重或数值精度：

- native-stream 已编码的文件通过原有 MaaS 原子发布器移动和校验，避免把 `[None]` 占位输出当作待编码帧。MaaS 推理先写请求独立的隐藏暂存文件，验证通过后才发布最终文件；失败清理暂存文件，不自动重试。
- 普通 HTTP 同样识别原生已编码结果，不进行二次编码。AdaLN 表模式复用共享的表选择器，核对条件和 scheduler。
- 在线15秒按既有接口交付360帧。视频流在分块提交时裁掉尾部padding，音频同步裁剪到15秒；不增加第二次转码或改变DiT采样。该输出上限默认关闭，离线原生362帧和NPU默认路径保留。
- MaaS输出目录遵循Python临时目录配置（Linux可设置`TMPDIR`），默认仍为`/tmp/generated_videos`，不再绕过部署方指定的临时磁盘。

CPU回归包含真实MP4原子发布／哈希保持、错请求文件拒绝、跨chunk裁剪与默认不裁剪、输出临时目录及已有MaaS路由。真实在线性能需分别记录完整预热、服务端推理／发布和HTTP提交／查询／下载；技术解码通过不等于人工精度认可。

已完成八卡、20步、Sage-FP8全并行Streaming与BF16 AdaLN表的12项在线矩阵，每项完整预热一次及正式一次。逐项性能、输入规格、交付帧数和精度复核状态见[公开结果](performance/h3-cuda-phaa-align16.md)。
