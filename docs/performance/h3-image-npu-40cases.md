测量日期：2026-11-12（北京时间）。本报告是已完成的发布前硬件矩阵；v0.6合入最新v0.5后，重新执行CPU分布式与配置回归，未重新跑40项NPU推理。发布检查见[发布说明](../H3-V06-RELEASE.md)。

## 1. 结果与测量口径

- **40项全部完成：36项生成成功，4项输入校验按预期拒绝，0 OOM。** 生成结果目视28项通过、8项部分符合；“通过”遵循正常图像与主要内容/编辑效果，不代表逐像素一致或严格身份保真。
- 原版与最终版共同成功35项：累计推理 **4,429.153 → 691.899秒，累计时延比6.401×**。CASE_032原版OOM，未混入这35项的加速比。
- 同一4卡常驻会话，每rank仅加载一次模型；初始化各rank最大值 **34.974秒**，单独记录。CASE_002为首请求，其余生成请求复用同一pipeline。144次rank-request的DiT NPU存储指针审计通过。
- 每项batch=1、seed=42、6个实际PDD去噪步骤、warmup=0、repeat=1。此表为全量矩阵的每项单次实测，不是上一轮2K探索多次请求的均值。
- 推理秒数：各rank同步后的pipeline耗时最大值；排除模型加载、JPEG文件打开和PNG保存。请求总耗时、PNG保存耗时及采样HBM/PSS保留在原始CSV。
- 显存allocated/reserved为各rank中最大单卡峰值，单位GiB；reserved受常驻会话此前请求影响。驱动HBM含context，不能和allocated直接互换。
- 单卡折算吞吐 = `3600 / (4 × 推理秒数)`，单位图/卡·小时，表示串行资源效率；没有测量并发服务吞吐。
- 历史原版与本轮使用的物理设备布局不同；原版部分用例为独立首请求，新版除CASE_002外为常驻复用。该全方案对比包含offload/常驻等差异，不能解释为某一个算子的独立加速。样本数不足以给出P95或统计显著性。

### 2.1 全量性能实际启用的特性

| 特性 | 作用与边界 | 对应开关 |
| --- | --- | --- |
| 精确六步AdaLN表 | 初始化预计算当前checkpoint六步布局，释放大AdaLN投影权重；不是视频的20/50步表 | --image_adaln_table |
| DiT常驻 | 避免推理过程中逐层CPU/NPU搬运 | --image_resident |
| 主DiT动态W8A8 | attention/FFN线性层量化，降低常驻显存；不是全模型INT8 | --image_int8 |
| 请求内条件/RoPE缓存 | 避免同一请求重复计算；成功或异常后均清理，不跨请求复用媒体结果 | --image_condition_cache |
| Token Refiner SP | 条件token分片计算 | --image_refiner_sp |
| Qwen视觉SP | 复用v0.5视觉SP适配 | --image_vision_sp |
| Image VAE空间tile并行 | 编码/ViT解码原tile跨卡分配；保持原tile几何和blend顺序 | --image_vae_parallel |
| FFN分块 | 以2048行分块限制临时激活 | --image_ff_chunk 2048 |
| RGB8输出传输 | 先沿用原量化器，再uint8 D2H；保持PIL resize行为 | --image_rgb8_output |
| 本地输入投影与原地打包 | 只投影SP rank拥有的图像行，避免全宽复制packed buffer；解决CASE_032容量问题 | --image_local_input |

最终全量**未启用**：纯Laser、Laser+SDPA-tail混合方案、fused QKV、native/Triton SwiGLU、fused RoPE、DiT TP2、SP2或allocator expandable segments。视频/音频Streaming未原样搬入Image，实际采用Image原空间tile并行。

常驻小输入allocated约37 GiB/卡，高于原offload约21 GiB/卡；W8A8相对BF16常驻约55 GiB/卡节省显存。

### 2.2 对应启动参数

```bash
torchrun --nproc_per_node=4 example/diffusers/infer_minimax_h3_image.py \
  --pretrained_model_name_or_path "$MODEL_ROOT" \
  --prompt "$PROMPT" --image_path_list "$REFERENCE_JPG" \
  --width 2048 --height 2048 --save_path "$OUTPUT_PNG" \
  --seed 42 --num_inference_steps 6 --warmup 0 --repeat 1 \
  --sp 4 --text_encoder_tp 4 --atten none \
  --image_adaln_table --image_resident --image_int8 \
  --image_condition_cache --image_refiner_sp --image_vision_sp \
  --image_vae_parallel --image_ff_chunk 2048 \
  --image_rgb8_output --image_local_input
```

下方统计对应上面列出的CLI参数；全量测量实际用常驻worker的 `load_pipeline(args)` 一次，再串行 `run_image(args, pipe)`。纯文本场景不传参考图；分辨率、prompt和min_generation_area按下方冻结Case变化。依赖与单项运行设置见[优化指南](../H3-IMAGE-NPU-OPTIMIZATIONS.md)；原始prompt、参考媒体和生成图片保留在私有归档，不随公开性能报告分发。
