# H3 三后端与 CUDA 默认切换验证

验证日期：2026-11-10。三后端均提供 CUDA/NPU 入口；CUDA 推荐的 T2VA/I2VA/R2VA 配方默认 native-stream，显式选择 legacy/lightning 仍可回退。NPU 原默认不变。

## 配置与回归

- 134 项 CPU 功能／配置回归通过；2 项 CUDA 专用 pytest 在 CPU 回归中跳过，真实硬件验证另列。
- 覆盖三后端×两硬件的参数校验、T2VA/I2VA/R2VA 推荐启动脚本、显式覆盖、服务参数传递、Wan 原参数、常驻后端切换拒绝、latent 输出旁路，以及 onload／编码／同步／offload 故障注入。
- 5 项旧核心 AST 兼容检查通过；13 个迁移解码方法通过上游数值方法 AST 核对。上游来源与适配文件哈希随代码保留，适配哈希使用 LF 换行的文件字节计算。
- 11 个 H3 shell 脚本通过 bash 语法检查；测试用例没有启动额外 GPU 工作。

## CUDA 真实整网冒烟

8×RTX 5090、SP8、Ref2VA 单参考图、1344×768、124 帧／24fps，每请求实际 1 次 DiT。主链路为 Sage-FP8 全并行预设，50 层 DiT 常驻；native decoder 的 146 个 Linear 使用原有 FP16 存储策略，其余参数 FP32，FP16 autocast。沿用原 InferenceManager，无诊断包装、无测试专用通信超时；同一进程连续两次请求。

| 请求 | 八 rank 最大调用耗时 s | 解码前准备 s | decoder H2D s | decoder＋输出 s | 返回 CPU master s |
|---|---:|---:|---:|---:|---:|
| 第一条，含模型初始化与首次形状触达 | 183.705 | 0.468 | 0.165 | 3.467 | 0.0024 |
| 第二条，复用常驻模型 | 11.477 | 0.335 | 0.161 | 3.970 | 0.0020 |

各阶段独立取八 rank 最大值，不能把这些最大值相加还原同一 rank 的总耗时。进程累计 allocated 峰值最高 29.142 GiB／卡，不是每条请求独立重置的峰值。两次请求后八 rank 的 CPU master 对象／指针稳定，DiT 参数和 buffer 全在 CUDA，跨请求设备指针稳定；请求内条件在 VAE 前释放。

两条视频均通过分辨率、帧数、视频完整解码和 SHA-256 记录；未进行音频评价。全部测试计算进程退出，八卡无计算进程。1-step 只验证完整链路、复用和容量，不证明视频生成质量，也不能替代 20／50 步性能或长时稳定性。

## 实际发现与处理

原生 FP32 整块 decoder 与全常驻 DiT 组合在权重 H2D 阶段发生过 OOM；因此 CUDA 推荐配方复用已有 decoder Linear FP16 存储，并与旧后端共用条件释放／空闲缓存回收回调，保留 DiT 常驻。失败清理始终尝试恢复 CPU master；失败 rank 不再先全设备同步，以免待完成 collective 隐藏原始错误。测试过程中另保留了一次未完成运行的证据；后续带定位信息及不带定位信息的两组连续请求分别完成，不据此宣称长期无卡死。

独立小尺寸存储对比为 256×256、13 帧：FP16 Linear 存储相对 FP32 存储，RGB8 最大差 1、平均绝对差 0.036314（0–255 标度），不逐像素相同。这是组件数值观测，不是用户对新默认成片的人工精度认可。

## NPU 与验证范围

八卡 910B3 的三后端、单图／五图来源 latent、5／10／15 秒共 18 项组件正式测试已通过技术检查，数据见 [NPU 性能表](h3-vae-npu.md)。另完成修改后两次单卡小尺寸 native 暂存调用，CPU master 复用通过，结束后八卡无计算进程。NPU 保留原生 FP32 权重与 FP16 autocast，不启用 CUDA Linear 存储策略。

CUDA T2VA/I2VA 新默认配置已完成启动参数回归，本轮真实整网新组合测试为 R2VA 单图 5 秒；其他任务／长形状、HTTP/MaaS 新后端整网容量与人工成片质量仍需各自验证。CUDA 历史三路组件对比见 [组件性能与精度](h3-omni-vae.md)，其中的权重存储、计时和音频范围与本页不同。
